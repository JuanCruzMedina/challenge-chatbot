# AGENTS.md — challenge-chatbot

Entry point for every coding agent working in this repository. It routes you to the file that owns each concern. Do not duplicate a rule from an owner file here: point to it.

## What this is

A multi-source chatbot for the challenge "Multi-Source Chatbot with Intelligent Agent Orchestration". It answers questions about a fictional software studio ("Demo Studio": 2 clients, 3 applications, 7 microservices, one product vision per client) and can perform actions. **All data is invented.** Never add real company, client or personal information.

## Workflow

1. **Spec-driven.** One OpenSpec change per step under `openspec/changes/<name>/`, proposed with `/opsx:propose` and implemented with `/opsx:apply`. Rules per artifact are in `openspec/config.yaml`.
2. **TDD.** Tests precede implementation.
3. **Git.** Work on a `feature/<name>` branch, never on `main`. Conventional Commits.
4. **Missing tooling is a blocker, not a suggestion.** If a required tool is unavailable (for example Ollama), stop and report it. Never simulate its output or silently skip the step.
5. **Task vs. docs conflict.** When a task conflicts with a routed file, stop and surface the conflict instead of improvising.

## Hard rules

- **No commit and no push without the user's explicit yes** for that changeset. Nothing is published.
- **Architecture invariants** (owner: `openspec/config.yaml`): informational queries through one RAG + KG tool; actions only through the MCP Server; the agent routes by tool-calling with no `if/else` or keyword routing; a new MCP tool never requires changing the agent; passive UI with no custom frontend.
- **Never spend money implicitly.** Automated tests use a fake LLM. Real-LLM runs are manual and opt-in (`LIVE_LLM=1`). The paid API is off by default (`docs/design-decisions.md → D9`).
- **Never install anything globally** without telling the user first (Ollama included). Use a local `uv` venv.
- **Invented data only.** No real names, clients, repos or credentials. Never commit `.env`.
- Code, comments, file names and docs in **English**. The conversation with the user is in Spanish.
- Repository docs must not reference machine-local paths or private tools outside this repo.
